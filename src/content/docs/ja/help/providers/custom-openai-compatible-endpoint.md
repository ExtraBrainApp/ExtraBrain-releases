プロバイダーまたはプロキシが OpenAI スタイルの API を公開する場合は、カスタム OpenAI-compatible エンドポイントを使用します。

![ExtraBrain ベース URL およびモデル名フィールドを使用したカスタム OpenAI-compatible プロバイダー設定](/assets/screenshots/help/dark/settings-custom-provider.png)

## 必須フィールド

| 分野 | 入力内容 |
| --- | --- |
| ベースURL | プロバイダーまたはプロキシ API ベース URL。 |
| API キー | そのエンドポイントに必要なキー。 |
| 機種名 | エンドポイントが予期する正確なモデル識別子。 |

## セットアップ手順

1. オンボーディングまたは **[設定] -> LLM プロバイダー** を開きます。
2. カスタム プロバイダー オプションを選択します。
3. ベース URL を入力します。
4. API キーを入力します。
5. モデル名を入力します。
6. 構成を検証します。
7. 短いテスト分析を実行します。

## よくある間違い

- プロバイダーが予期しているときに `/v1` がありません。
- API モデル識別子の代わりにモデル表示名を使用します。
- 間違ったプロバイダーまたはプロキシのキーを貼り付けます。
- プロバイダーの保持、請求、およびアクセス ルールがカスタム エンドポイント オペレーターによって制御されていることを忘れています。

カスタム プロバイダー リクエストには、プロンプト、トランスクリプト コンテキスト、スクリーンショットから派生したコンテキスト、およびカスタムの質問を含めることができます。

## カスタムエンドポイントの質問

### エンドポイントが OpenAI-compatible になるのはなぜですか?

エンドポイントは、ExtraBrain に入力したベース URL、キー、およびモデル名を使用して、チャットまたは応答に対する OpenAI スタイルの API リクエストを受け入れる必要があります。

### カスタム エンドポイントを保存した後は何をテストすればよいですか?

機密性の低いトランスクリプトまたはスクリーンショットのコンテキストを使用して短い分析を実行します。エンドポイントが応答を返し、モデル名がプロバイダーまたはプロキシが期待するものと一致することを確認します。
