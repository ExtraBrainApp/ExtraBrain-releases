Використовуйте спеціальну кінцеву точку OpenAI-compatible, коли ваш постачальник або проксі надає API у стилі OpenAI.

![ExtraBrain спеціальні налаштування постачальника OpenAI-compatible з полями базової URL-адреси та назви моделі](/assets/screenshots/help/dark/settings-custom-provider.png)

## Обов'язкові поля

| Поле | Що ввести |
| --- | --- |
| Базовий URL | Основна URL-адреса постачальника або проксі API. |
| Ключ API | Ключ, необхідний для цієї кінцевої точки. |
| Назва моделі | Точний ідентифікатор моделі, який очікує кінцева точка. |

## Етапи налаштування

1. Відкрийте адаптацію або **Налаштування -> LLM Постачальники**.
2. Виберіть власний варіант постачальника.
3. Введіть базову URL-адресу.
4. Введіть ключ API.
5. Введіть назву моделі.
6. Перевірте конфігурацію.
7. Виконайте короткий тестовий аналіз.

## Поширені помилки

- Відсутній `/v1`, коли постачальник очікує його.
- Використання відображуваної назви моделі замість ідентифікатора моделі API.
- Вставлення ключа для неправильного постачальника або проксі.
- Забуваючи, що правила утримання постачальника, виставлення рахунків і доступу контролюються спеціальним оператором кінцевої точки.

Спеціальні запити постачальника можуть містити підказки, контекст стенограми, контекст, отриманий зі знімка екрана, і спеціальні запитання.

## Запитання про користувацькі кінцеві точки

### Що робить кінцеву точку OpenAI-compatible?

Кінцева точка повинна приймати запити API у стилі OpenAI для чату або відповіді, використовуючи базову URL-адресу, ключ і назву моделі, які ви вводите в ExtraBrain.

### Що слід тестувати після збереження спеціальної кінцевої точки?

Виконайте короткий аналіз із неконфіденційною розшифровкою або контекстом знімка екрана. Переконайтеся, що кінцева точка повертає відповідь і що назва моделі відповідає очікуванням вашого постачальника або проксі.
